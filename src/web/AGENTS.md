# Repository Guidelines

These guidelines are the quick-reference for contributors and automation agents. For authoritative, detailed instructions also see `.github/copilot-instructions.md`.

## Project Structure & Module Organization

- Source: `src/` (SvelteKit). Key areas: `src/routes/` (pages, API via `+server.ts`), `src/lib/` (components, utilities, server helpers, i18n), and `src/lib/game-static-info.json`.
- Assets: `static/` (favicon, sprites, public files).
- Database: `drizzle/` (migrations), config in `drizzle.config.ts`.
- i18n: raw messages in `messages/`, project config in `project.inlang/`, generated code in `src/lib/paraglide/` (auto-generated; do not edit).
- Tools: `tools/` (scripts like sprite importer and related tests).

## Required Environment Setup

Create a `.env` file in the project root with these exact variables before any operations:

```
PRIVATE_DOTNET_API_BASE_URL=http://localhost:5000
PUBLIC_SPRITES_BASE_URL=/sprites
DATABASE_URL=sqlite:dev.db
```

## Development Workflow

### Initial Setup (run in this order)

- `npm ci` — installs dependencies
- `npm run db:migrate` — creates/updates the SQLite database

Note: Paraglide i18n files are auto-generated by a Vite plugin during build/dev. If you see missing module errors for `$lib/paraglide/messages`, run any Vite command (`npm run dev`, `npm run build`, or `npm run check`).

## Build, Test, and Development Commands

- `npm run dev`: Start local dev server with Vite/SvelteKit.
- `npm run build`: Production build; output in `.svelte-kit/` and adapter target.
- `npm run preview`: Preview the built app locally.
- `npm run check`: Type-check with `svelte-check` and sync SvelteKit.
- `npm run lint` / `npm run format`: ESLint + Prettier check/format.
- `npm run test` / `npm run test:run`: Run Vitest (watch/CI). `npm run coverage` for coverage.
- `npm run db:push|db:migrate|db:studio`: Drizzle schema management and studio.
- `npm run import-sprites`: Import/transform sprite assets.
- `npm run machine-translate`: Generate translations via Inlang.

## Manual Validation Requirements

Always perform these after making changes:

1. Build validation: `npm run build` (never cancel)
2. Test validation: `npm run test:run`
3. Application testing:
   - Start `npm run dev`
   - Open `http://localhost:5173`
   - Verify homepage shows "Welcome to the Game Randomizer!"
   - Click "Get Started" to reach config page
   - Expected (without backend): "Failed to communicate with backend" error
4. Linting/formatting: `npm run format` before committing

## Coding Style & Naming Conventions

- Languages: TypeScript, Svelte 5, Tailwind CSS.
- Indentation: 2 spaces; follow ESLint and Prettier defaults (`npm run format`).
- Files: Svelte components `PascalCase.svelte`; general modules `kebab-case.ts`; SvelteKit routes use `+page.svelte`, `+layout.svelte`, `+server.ts` patterns.
- Server-only utilities live in `src/lib/server/`; shared types in `src/lib/types.ts`.

## Testing Guidelines

- Framework: Vitest (`vitest.config.ts`). Tests currently focus on `tools/sprite-importer` and use `*.test.ts`.
- Run: `npm run test` during development; `npm run coverage` for reports.
- Add tests alongside code or in a nearby `__tests__` folder; prefer fast, unit-level tests.

## Commit & Pull Request Guidelines

- Commits: Imperative, concise subject (≤72 chars), include scope when useful (e.g., `routes: fix seed link`).
- PRs: Clear description, linked issues, steps to reproduce/test, and screenshots/GIFs for UI changes. Include migration notes when touching `drizzle/`. Update docs and i18n if affected.

## Security & Configuration Tips

- Keep secrets in environment variables; never commit credentials. Review auth flows (Lucia) and DB access (Drizzle) in server code only. Validate all API input in `+server.ts` endpoints.

## Sprite Tools (Remote Workflow)

- Location: `tools/sprite-importer/` with CLI `npm run import-sprites -- ...`.
- Repo layout: Remote repo stores per-game data under `<repo>/<game>/`; `sprites.json` lives at `<repo>/<game>/sprites.json` with paths relative to that game folder.
- Auth: Set `SPRITE_IMPORTER_GITHUB_PAT` (scoped for repo push). Use HTTPS repo URLs.
- Init game folder:
  - `npm run import-sprites -- remote init --repo <url> --game alttp --sourceDir .`
- List sprites:
  - `npm run import-sprites -- remote list --repo <url> --game alttp --sourceDir .`
- Add/update sprite (RDC required; PNG optional — auto-render for ALttP/SM if omitted):
  - `npm run import-sprites -- remote add --repo <url> --game alttp --spriteName MySprite --sourceRdc ./out/my.rdc --sourcePng ./out/my.png --sourceDir .`
- Bulk add/update from a directory in one commit:
  - `npm run import-sprites -- remote bulk-add --repo <url> --game alttp --sourceDir ./out/rdc`
- Remove sprite:
  - `npm run import-sprites -- remote remove --repo <url> --game alttp --spriteName MySprite --sourceDir .`
- Dry-run mode (no writes, logs intent): append `--dryRun` to any remote subcommand.

## Timing Expectations and Timeouts

- `npm ci`: ~40s (timeout ≥ 5m)
- `npm run build`: ~12s (timeout ≥ 30m; never cancel)
- `npm run test:run`: ~11s (timeout ≥ 30m)
- `npm run check`: ~15s (timeout ≥ 10m)
- `npm run lint`: ~15s (timeout ≥ 10m)
- `npm run dev`: startup ~3s (timeout ≥ 2m)

## Docker and Deployment

There is Docker Compose for production deployment:

```
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```

Required env vars for production: `DOMAIN`, `TRAEFIK_ACME_EMAIL`, `API_IMAGE`, `FRONTEND_IMAGE`.

## Troubleshooting Common Issues

- "Cannot find module `$lib/paraglide/messages`": run `npm run dev` or `npm run build` to generate Paraglide files.
- "DATABASE_URL is not set": ensure `.env` has `DATABASE_URL=sqlite:dev.db` and run `npm run db:migrate`.
- Backend API errors during dev: expected if the .NET backend isn’t running; the frontend still functions.
- Sprite importer GitHub operations: set `SPRITE_IMPORTER_GITHUB_PAT`.

## CI/CD Integration

GitHub Actions run lint, typecheck, tests, and build on each push/PR. Before pushing, run:

```
npm run lint && npm run check && npm run test:run && npm run build
```
